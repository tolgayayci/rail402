An open-source [x402](https://x402.org) facilitator for Stellar, a **Bazaar** discovery layer, and
an MCP server that lets an agent find and pay for a service it has never seen before.

Apache-2.0, self-hostable, and forkable end to end — including the maintenance system that keeps it
conformant.

<Callout type="warn" title="Documentation in progress">
  The project is still under active development. This overview is accurate; several sections below
  are stubs and are marked as such. Nothing here describes behaviour that does not exist — where
  something is unbuilt, it says so.
</Callout>

## What problem this solves

An agent with a budget can pay for an API today. What it cannot reliably do is **find one**. That is
the gap this project targets, and it is measurably unfilled:

| | Across the x402 ecosystem |
|---|---|
| Facilitators serving `/discovery/search` | **1** of 9 probed |
| Largest catalog's working filters | **0** of 7 |
| MCP tools catalogued anywhere | **0** of 15,336 |

Search is the part existing catalogs leave unimplemented. Filtering is mostly unimplemented too.

## Becoming discoverable

There is no registration step, no dashboard and no API key. A seller adds **one key** to a route
they already have, and is catalogued the first time somebody pays:

```ts
import { describeEndpoint } from "@x402-stellar/seller-helpers";

"GET /premium/quote": {
  accepts: {
    scheme: "exact",
    network: "stellar:testnet",
    price: { amount: "2500000", asset: ASSET },
    payTo: PAY_TO,
  },
  description: "A price quote for a named commodity.",
  extensions: describeEndpoint({
    params: {
      symbol: { description: "Ticker symbol to price, such as XLM, BTC or GOLD.", example: "XLM" },
    },
  }),
}
```

Cataloging triggers on **successful settlement**, which is what makes listings expensive to forge:
every entry cost a real on-chain payment.

The trade-off is worth stating plainly — a resource nobody has ever paid for is not in the catalog.
That is deliberate, and it means this catalog will never win on raw size against a service that lets
anyone POST a URL.

## Measured, not asserted

Every number below is produced by a check that runs nightly against live testnet and publishes
machine-readable evidence. Nothing here is described as working on the strength of a passing unit
test.

| | |
|---|---|
| Zero to a paid, **discoverable** endpoint | **29.2s** (target: under an hour) |
| Indexing lag, settlement → catalogued | **2ms** |
| Rejection paths carrying a code **and** an actionable reason | **17 / 17** |
| Search precision@1 on a held-out corpus of real resources | **90%** |

The last one is the honest one. A curated corpus written in-house scores 100%; a held-out slice of
twenty **real** catalog entries — where `serviceName` appears on 1 of 20 and per-parameter
descriptions on 2 of 20 — scores 90%. That gap is reported rather than averaged away.
