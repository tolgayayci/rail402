---
title: "Run your own Explorer"
description: "Run the Rail402 Explorer yourself with Docker. A read-only observer of x402 payments on Stellar that holds no keys, needs no facilitator, and indexes the whole ecosystem, not just one operator's slice."
---

The [Explorer](/explorer/overview) is a read-only service. It watches the ledger, classifies every x402 settlement structurally, and attributes each to the facilitator that submitted it. Running your own gives you the same view the hosted one has, on infrastructure you control.

It holds **no secrets and no keys**. It reads public Soroban RPC, public Horizon, and public facilitator `/supported` endpoints, and it moves no funds. Because it classifies payments by their on-chain shape rather than an allowlist, your instance sees traffic from every facilitator, including ones nobody registered. It is a separate image and a separate deployment from the facilitator, sharing no database and no runtime code path.

The one thing it needs is a writable directory for its SQLite database. That database is the system of record: Soroban RPC forgets after roughly seven days, and a testnet reset wipes everything upstream, so the volume is what makes your history durable.

## Run one

The Explorer ships as a Docker image. The only setting that matters for a real deployment is a persistent volume for the database.

<CodeGroup>
```bash Published image
docker run -p 8080:8080 \
  -v rail402-explorer-data:/data \
  ghcr.io/tolgayayci/rail402-explorer
```

```bash Build from source
# from a Rail402 checkout
docker build -f Dockerfile.explorer -t rail402-explorer .

docker run -p 8080:8080 \
  -v rail402-explorer-data:/data \
  rail402-explorer
```
</CodeGroup>

<Note>
The published `ghcr.io/tolgayayci/rail402-explorer` image is built and pushed with each tagged release. Before the first release, or to run an unreleased change, use the build-from-source path. Both produce the same image; the Dockerfile sets `EXPLORER_DB_PATH=/data/explorer.db` so the mounted volume is used automatically.
</Note>

That is a complete public `stellar:testnet` explorer. It runs as root because managed hosts mount volumes root-owned and a non-root user cannot open a database file under such a mount; container isolation is the platform's job.

## Verify it

```bash
curl http://localhost:8080/health
curl "http://localhost:8080/feed?limit=5"
```

`/health` reports the storage mode, the networks watched, and per-network ingest state:

```json
{ "status": "ok", "storage": "durable", "payments": 0, "ingest": [{ "network": "stellar:testnet", "lastLedger": 0, "backfill": "running" }] }
```

`storage` must read `durable` on a real deployment. `memory` means the volume or `EXPLORER_DB_PATH` is missing and a restart will forget all history. `degraded` means several consecutive RPC polls failed on some network.

`/metrics` is Prometheus. The two series worth alerting on are `x402_explorer_rpc_failures_total` and the staleness of `x402_explorer_last_ledger{network}`.

<Warning>
The first run fills slowly. The Explorer replays the whole roughly-seven-day RPC window and walks each known facilitator's history in passes, so a fresh deployment takes several minutes before the full window is present. A transaction that is still being backfilled returns `404 explorer_tx_not_found`, marked retryable. It is filling, not missing.
</Warning>

## Configuration

Every variable has a working default, so the command above runs with none of them. Set `EXPLORER_DB_PATH` on any real deployment. These are the ones you are most likely to touch:

| Variable | Default | Why you'd change it |
| --- | --- | --- |
| `EXPLORER_DB_PATH` | in-memory | **Set it.** Unset means a restart forgets all history. The Docker image sets `/data/explorer.db` for you. |
| `PORT` | `4040` (Docker: `8080`) | The port the read API binds. |
| `EXPLORER_NETWORKS` | `stellar:testnet` | Comma-separated CAIP-2 ids to observe. Add `stellar:pubnet` to watch mainnet. |
| `EXPLORER_FACILITATOR_SEEDS` | Rail402 + x402.org | Watch additional facilitators from boot. Any facilitator can also self-register via `POST /announce`. |
| `EXPLORER_BAZAAR_URL` | `facilitator.rail402.dev` | Point seller enrichment at a different Bazaar, or set `""` to turn enrichment off. |
| `EXPLORER_INGEST_ENABLED` | `true` | Set `false` for an API-only server that serves an existing database without tailing the ledger. |
| `CORS_ORIGINS` | `*` | Restrict who may call the API from a browser. The default is open because this is public data. |

A network with no built-in defaults is one JSON entry away, with no code change:

```bash
EXPLORER_NETWORK_CONFIG='{"stellar:testnet":{"rpcUrl":"https://your-rpc.example","horizonUrl":"https://your-horizon.example"}}'
```

## Watch mainnet

The same image observes `stellar:pubnet`; it is a change of configuration, not code. Two things differ from testnet. Pubnet public RPCs rate-limit, so demand must be paced, and pubnet carries hundreds of transfer events per ledger, so the tail is filtered to the assets x402 actually settles in (USDC and EURC, both built in).

```bash
docker run -p 8080:8080 -v rail402-mainnet-data:/data \
  -e EXPLORER_NETWORKS=stellar:pubnet \
  -e EXPLORER_BAZAAR_URL= \
  -e EXPLORER_KNOWN_UPTO_CONTRACTS= \
  -e EXPLORER_RPC_MAX_RPS=6 \
  -e EXPLORER_BACKFILL_MAX_LEDGERS=0 \
  -e EXPLORER_BACKFILL_PAGE_DELAY_MS=1000 \
  ghcr.io/tolgayayci/rail402-explorer
```

`EXPLORER_BAZAAR_URL=` is empty on purpose: a testnet catalog must not name mainnet sellers. `EXPLORER_KNOWN_UPTO_CONTRACTS=` is empty because no `upto` settlement contract is deployed on pubnet. `EXPLORER_RPC_MAX_RPS` paces RPC demand evenly across the live tail and the backfill so a shared public endpoint does not rate-limit you.

History deeper than the RPC retention window comes from Horizon account walks. A facilitator whose `/supported` is unreachable or key-gated cannot be verified, but its constant fee-bump fee account is public on chain, and Horizon indexes fee sources as participants, so one watch account covers an entire rotating channel pool:

```bash
-e EXPLORER_WATCH_ACCOUNTS='{"stellar:pubnet":["G...FEE_ACCOUNT","G...SELLER_PAYTO"]}'
```

Rows recovered this way are classified by the same structural classifier and stay honestly `x402-shaped`; a watch account is an observation lead, never an attribution.

## Appear on an explorer

An explorer discovers facilitators, not the other way around, so there is nothing to register to be *watched* — but a facilitator can announce itself so an explorer starts probing it immediately.

If you run the Rail402 facilitator, point it at your explorer:

```bash
FACILITATOR_PUBLIC_URL=https://your-facilitator.example.com
# EXPLORER_ANNOUNCE_URL defaults to the hosted Rail402 explorer; set "" to opt out.
```

The heartbeat sends only that public URL. The explorer probes `/supported` itself and trusts only what it verifies on chain. Any other facilitator can register with a single call:

```bash
curl -X POST http://localhost:8080/announce \
  -H 'Content-Type: application/json' \
  -d '{"baseUrl":"https://your-facilitator.example.com"}'
```
