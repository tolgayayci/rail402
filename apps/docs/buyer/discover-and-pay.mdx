The [Buyer quickstart](/buyer/quickstart) pays an endpoint you already know. This page finds one you do not, then pays it. Discovery is two GET endpoints with no authentication, so you can call them from a script or a browser.

## Browse the catalog

`GET /discovery/resources` returns the catalog, filtered and paginated.

```bash
curl -s "https://facilitator.rail402.dev/discovery/resources?type=http&limit=3"
```

```json
{
  "x402Version": 2,
  "items": [
    {
      "resource": "https://your-seller.example/quote",
      "type": "http",
      "accepts": [
        {
          "scheme": "exact",
          "network": "stellar:testnet",
          "amount": "500000",
          "asset": "CBIELTK6YBZJU5UP2WWQEUCYKLPU6AUNZ2BQ4WWFEIE3USCIHMXQDAMA",
          "payTo": "GBOQSB3F...QR2",
          "maxTimeoutSeconds": 60,
          "extra": { "areFeesSponsored": true }
        }
      ],
      "description": "A price quote for a named commodity, in a chosen currency.",
      "lastUpdated": "2026-08-13T18:52:28.889Z",
      "quality": { "totalSettlements": 1, "uniquePayers": 1 }
    }
  ],
  "pagination": { "limit": 3, "offset": 0, "total": 8 }
}
```

The filters are `type` (`http` or `mcp`), `payTo`, `scheme`, `network`, `extensions`, `limit`, and `offset`. `limit` defaults to 20 and caps at 100. Pagination is by offset: read `pagination.total`, then step with `offset`.

## Search in natural language

`GET /discovery/search` ranks the catalog against a natural-language `query`. The `query` parameter is required.

```bash
curl -s "https://facilitator.rail402.dev/discovery/search?query=current%20price%20of%20a%20commodity"
```

```json
{
  "x402Version": 2,
  "resources": [ { "resource": "https://your-seller.example/quote", "accepts": [ ... ], "description": "..." } ],
  "pagination": { "limit": 20, "cursor": "eyJvIjoyLCJxIjoiMXR1NGVsdSJ9" },
  "searchMethod": "hybrid (bm25+static-embedding, rrf)"
}
```

Two things about the response shape are load-bearing:

- The result array is `resources`, not `items`. The browse endpoint uses `items`. The stock `withBazaar()` client depends on this difference.
- Pagination is by opaque `cursor`, bound to your query and filters. Pass it back as `?cursor=` for the next page. When there is no next page, `pagination` is `null`.

`partialResults: true` appears only when the facilitator truncated the result set, not merely when another page exists. Ranking is a hybrid of weighted-field BM25 and a static-embedding vector arm, fused by reciprocal rank fusion, which `searchMethod` reports honestly.

## Read a result before you pay

Every result carries what you need to call it:

- `resource` is the URL to pay.
- `accepts` lists the payment options. Read `amount` (in atomic units), `asset`, `scheme`, and `payTo`. A Stellar `exact` option you can pay carries `extra.areFeesSponsored: true`.
- The per-parameter descriptions live under the bazaar extension schema, at `input.properties.queryParams.properties.<name>.description`. Read them to build a valid call to an endpoint you have never seen.

## Pay a metered service with `upto`

`exact` charges a fixed price. `upto` fits metered services such as token billing: you authorize a **ceiling**, and only the **actual** usage settles.

You sign an authorization for the ceiling once. The seller reports the real usage at settlement, the on-chain contract charges that amount, and it re-checks that the actual charge never exceeds the ceiling you signed. The unused difference never leaves your wallet. Each authorization is single-use, so it cannot be settled twice, and a zero-usage settlement still consumes the authorization and moves no money.

## The Rail402 agent helpers

The Rail402 repository ships `@rail402.dev/agent-helpers`, which wraps search, pay, and the spend cap into three functions. It is not on npm. Use it when you work inside the repository.

```ts
import { searchBazaar, payAndFetch, discoverAndPay } from "@rail402.dev/agent-helpers";

const config = {
  bazaarUrl: "https://facilitator.rail402.dev",
  stellarSecret: process.env.CLIENT_STELLAR_PRIVATE_KEY, // G-account secret
  network: "stellar:testnet",
};

// Search only. Pays nothing.
const found = await searchBazaar(config, "current price of a commodity by ticker", { limit: 5 });

// Pay a known URL, capped.
const paid = await payAndFetch(config, "https://your-seller.example/quote", {
  maxAmount: "1000000",              // required, no default
  queryParams: { symbol: "XLM" },
});

// Search, pick the best match, and pay it, in one call.
const result = await discoverAndPay(config, "translate text to spanish", { maxAmount: "1000000" });

if (!paid.ok) console.error(paid.error.code, paid.error.reason);
else console.log(paid.data.body, paid.data.paid.transaction);
```

`maxAmount` is required and has no default. A default would make an unbounded spender by omission. The cap is read from an unpaid probe first, so an over-budget resource costs one HTTP request and no money, and it is re-applied to the price quoted at the moment of payment. Both quotes must fit the cap or nothing is signed.

Every result is `{ ok, data?, error? }`, and every error is `{ code, reason, retryable }`. Branch on `code`, never on the message. Respect `retryable`: a replayed authorization or a budget refusal is never retryable, and retrying it wastes requests. See [Rejection reasons](/reference/errors) for the full list.

<Note>
These helpers sign with a classic keypair, so they pay from a `G...` account. The facilitator itself settles payments from smart-contract (`C...`) accounts too, and the `oz-account` canary proves it. Paying from a smart account through these buyer-side helpers is not yet wired.
</Note>
