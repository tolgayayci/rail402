---
title: In-process facilitator
description: Verify and settle inside your own resource server, with no HTTP facilitator.
---

`@rail402.dev/facilitator` is the settlement engine the service runs. A resource server can run it in its own
process and call it through `inProcessClient`, a stock x402 `FacilitatorClient`. Verification and settlement
run the same checks with the same codes as over HTTP (stages 1 to 8 of
[Errors and verification rules](/verification-rules)), without the network hop. The HTTP request checks
(stage 0) and the Bazaar are part of the service and are not included.

The seller then holds a sponsor seed and pays its own settlement fees. Use this when you want no dependency on
an external facilitator; otherwise point `HTTPFacilitatorClient` at a Rail402 instance.

```sh
npm install @rail402.dev/facilitator
```

The package runs on Node.js 24.11 or later. For durable settlement across processes, add
`@rail402.dev/store-postgres` (see [Options](#options)).

## Example

An `@x402/express` seller that settles its own payments on testnet. The seller's dependencies are the same
as in the [seller quickstart](/quickstart/sellers#1-install), plus `@rail402.dev/facilitator`:

```sh
npm install express@5 @x402/express@2.29.0 @x402/core@2.29.0 @x402/stellar@2.29.0 @stellar/stellar-sdk@16.4.1 @rail402.dev/facilitator@0.5.2
```

```ts server.ts
import express from "express";
import { Keypair, Networks, rpc } from "@stellar/stellar-sdk";
import { x402ResourceServer } from "@x402/core/server";
import { paymentMiddleware } from "@x402/express";
import { ExactStellarScheme } from "@x402/stellar/exact/server";
import {
  createStellarFacilitator,
  deriveChannelKeypairs,
  inProcessClient,
  provisionChannels,
} from "@rail402.dev/facilitator";

const NETWORK = "stellar:testnet";
const RPC_URL = "https://soroban-testnet.stellar.org";
const CHANNELS = 2;
const sponsor = Keypair.fromSecret(process.env.SPONSOR_SECRET!);

// Channel accounts are derived from the sponsor. Create the missing ones; the sponsor pays their reserves.
await provisionChannels({
  server: new rpc.Server(RPC_URL),
  passphrase: Networks.TESTNET,
  sponsor,
  channels: deriveChannelKeypairs(sponsor, NETWORK, CHANNELS),
});

const facilitator = createStellarFacilitator({
  networks: [{ network: NETWORK, rpcUrl: RPC_URL, sponsorSecret: sponsor.secret(), channelCount: CHANNELS }],
});
// Finishes settlements that answered `settlement_pending`.
setInterval(() => void facilitator.reconcile(), 5_000).unref();

const resourceServer = new x402ResourceServer(inProcessClient(facilitator)).register(
  NETWORK,
  new ExactStellarScheme(),
);

const app = express();
app.use(
  paymentMiddleware(
    {
      "GET /weather": {
        accepts: { scheme: "exact", price: "$0.01", network: NETWORK, payTo: process.env.PAY_TO! },
        description: "Weather report",
        mimeType: "application/json",
      },
    },
    resourceServer,
  ),
);
app.get("/weather", (_req, res) => {
  res.json({ weather: "sunny", temperature: 21 });
});
app.listen(4021);
```

`SPONSOR_SECRET` is the seed of a funded testnet account and `PAY_TO` an account with a USDC trustline. The
buyer quickstart's [`create-account.ts`](/quickstart/buyers#2-create-a-funded-testnet-account), run with no
amount, creates either: a Friendbot-funded account (the sponsor needs only its XLM) with a USDC trustline. The stock buyer from the
[buyer quickstart](/quickstart/buyers) pays this server unchanged.

## Options

`createStellarFacilitator({ networks, log, observer })` takes one entry per network. The optional `observer`
is a `SettlementObserver` that receives each settlement's channel lease wait, submissions, final state, fee
charged, reconciliation outcome, the number of unresolvable settlements after each reconciliation pass, and
repeats, for your own metrics; the service's Prometheus metrics are built
on it (`apps/rail402/src/metrics.ts`).

| Field                         | Required         | Default                                                                                                            | Meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ----------------------------- | ---------------- | ------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `network`                     | yes              |                                                                                                                    | `"stellar:testnet"` or `"stellar:pubnet"`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `rpcUrl`                      | yes              |                                                                                                                    | Stellar RPC URL; pubnet requires `https`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `sponsorSecret`               | yes              |                                                                                                                    | The sponsor's `S…` seed                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `channelCount`                | yes              |                                                                                                                    | Channel accounts, i.e. settlements that can be in flight at once                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `assets`                      | no (pubnet: yes) | testnet: Circle USDC; pubnet: none                                                                                 | `acceptedAsset({ contract, symbol, decimals }, { minAmount, maxAmount })` entries. Pubnet refuses to start without at least one; set `minAmount` there to bound dust payments (it defaults to 1 base unit)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `policy`                      | no (pubnet: yes) | `{ min: 10, max: 300 }` s timeouts, 1 ledger margin, 300,000 stroop fee ceiling, 100 stroop inclusion fee          | `timeoutSeconds`, `expirationMarginLedgers`, `maxTransactionFeeStroops`, `inclusionFeeStroops`. On pubnet `maxTransactionFeeStroops` and `inclusionFeeStroops` (at least 200) must be set                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `ledger`                      | no               | in-memory                                                                                                          | Settlement ledger: idempotency and crash recovery                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `channels`                    | no               | in-memory                                                                                                          | Channel pool: leases channel accounts to settlements                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `timing`                      | no               | `channelWaitMs` 5000, `claimTtlMs` 30000, `confirmTimeoutMs` 25000, `duplicateWaitMs` 25000, `pollIntervalMs` 1000 | Settlement waits in milliseconds: for a free channel, before an unsigned claim may be taken over, for confirmation before `settlement_pending`, for a duplicate request's original, and between confirmation polls                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `inclusionFee`                | no               | fixed bid from `policy`                                                                                            | `{ floor, cap, percentile }`: bid from the network's recent fee stats                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `guard`                       | no (pubnet: yes) | none                                                                                                               | Refuses settlements while the sponsor cannot pay for them, e.g. `SponsorBudget` (with `refuseWhileUnknown: true` on pubnet) or `SettleLimits` around it. Pubnet refuses to start without one unless `unguarded: true`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `unguarded`                   | no               | `false`                                                                                                            | Pubnet only: run without a `guard`, accepting that nothing bounds what the sponsor spends                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `allowInclusionFeeBelowFloor` | no               | `false`                                                                                                            | Pubnet only: accept an inclusion fee (or `inclusionFee.floor`) below 200 stroops                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `rpc`                         | no               | one provider, `rpcUrl`                                                                                             | An `RpcPool` of several providers; each settlement uses the one active when it was claimed (see [RPC providers](/operations#rpc-providers))                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `upto`                        | no               | not served                                                                                                         | Serve `upto` too: `{ contract, contractWasmHash, zeroSettlement, maxTransactionFeeStroops, ledgerSeconds }`. `contract` and `contractWasmHash` default to the canonical deployment on testnet; any other contract needs its `contractWasmHash` (startup refuses it otherwise), and pubnet also needs `maxTransactionFeeStroops`; `zeroSettlement` is `onchain` (default) or `offchain`; the fee ceiling defaults to 500,000 stroops; `ledgerSeconds` (a number or a callback) defaults to the average close time over the ledgers `rpcUrl` retains, read at most once a minute (5 s when the RPC cannot tell), so no other service is asked. The in-memory ledger and channel pool suit one process that can lose its state on restart. For durable,
multi-process settlement, pass the Postgres stores the service itself uses, from `@rail402.dev/store-postgres`
(`PostgresSettlementLedger`, `PostgresChannelPool`, `createDatabase`, `migrate`); see
`apps/rail402/src/runtime.ts` for how the service wires them.

Before serving `upto` with a contract of your own, check that it is live and runs the WASM you
configured: `await assertUptoContract(server, contract, contractWasmHash)` throws `UptoContractCheckError`
(`reason` `absent` or `wasm_mismatch`) otherwise. The contract has no admin and cannot be upgraded, so this
one check pins what every `upto` payment runs. The Rail402 service runs it at startup and refuses (or, with
several networks, holds) pubnet when the contract is absent or runs other code.

## Access, limits and service fees

The service's access keys, request limits and metering are HTTP features. In-process, the facilitator runs
inside your server, so your server authenticates its own callers, and the facilitator gives it the same
settlement controls the service uses: who a settlement is for, how much each caller and the network may
cost the sponsor, how fast one payer may settle, which tokens are accepted, and the service fee recorded
with each settlement.

| Control           | In-process                                                                                                                                                                                                                                                                                      |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Authentication    | Your server's own. Authenticate the request as you do for any route, refuse it when that fails, and run the settlement inside `withCaller({ subject }, () => …)` so the facilitator records who it was for. A settlement outside `withCaller` is recorded for `public`                          |
| Per-caller budget | `sponsorBudgetStroopsPerHour` in the `withCaller` context: the fees that caller's settlements may commit per hour, enforced by `SponsorBudget` together with each claim. Refused with `settle_exact_stellar_caller_budget_exhausted` (`settle_upto_stellar_caller_budget_exhausted` for `upto`) |
| Sponsor limits    | `guard: new SponsorBudget({ network, ledger, balance, minBalanceStroops, maxSpendPerHourStroops, keylessSpendPerHourStroops, refuseWhileUnknown })`: a reserve floor, the network's hourly fee budget, and a budget shared by every settlement that runs outside `withCaller` or as `public`    |
| Rate limits       | `new SettleLimits({ network, inner: budget, take, payerPerMinute, payToPerMinute, failuresPerHour, ledger, failClosed })` around the budget: settlements per payer and per `payTo` per minute, and a cooldown for a payer whose settlements keep failing on-chain. `take` is your counter       |
| Accepted assets   | `assets`: any other token is refused with `invalid_exact_stellar_requirements_asset_not_accepted`, and an amount outside `minAmount`…`maxAmount` with `invalid_exact_stellar_requirements_amount_out_of_range`                                                                                  |
| Service fees      | `serviceFeeUsd` in the `withCaller` context: recorded with each settlement as priced when it was claimed. `ledger.usageSince(caller, since)` returns each caller's succeeded settlements, sponsored fees and accrued service fees per network and day                                           |

Request rate limits on your routes (per address or per credential) stay your server's, as for any other
route.

```ts
import {
  SettleLimits,
  SponsorBudget,
  withCaller,
  MemorySettlementLedger,
  type CallerContext,
} from "@rail402.dev/facilitator";
// NETWORK, `facilitator` and `app` as in the example above; `client = inProcessClient(facilitator)`.

const ledger = new MemorySettlementLedger();
let sponsorBalance: bigint | undefined; // refreshed by your own poll of the sponsor account
const guard = new SettleLimits({
  network: NETWORK,
  inner: new SponsorBudget({
    network: NETWORK,
    ledger,
    balance: () => sponsorBalance,
    minBalanceStroops: 250_000_000n, // 25 XLM
    maxSpendPerHourStroops: 100_000_000n, // 10 XLM
    refuseWhileUnknown: true,
  }),
  take: (key, perMinute) => myLimiter.take(key, perMinute), // 0 = allowed, else seconds to wait
  payerPerMinute: 10,
  failClosed: true,
});
// Pass `ledger` and `guard` in the network's setup.

// Your credential → the caller its settlements run as.
const callers = new Map<string, CallerContext>([
  [
    "<key of acme>",
    { subject: "key:acme", sponsorBudgetStroopsPerHour: 20_000_000n, serviceFeeUsd: "0.001" },
  ],
]);

app.post("/pay", async (req, res) => {
  const caller = callers.get(req.get("x-api-key") ?? "");
  if (caller === undefined) return res.status(401).end();
  const result = await withCaller(caller, () => client.settle(req.body.payload, req.body.requirements));
  res.json(result);
});
```

`withCaller` covers every settlement started inside its callback, including through awaited calls. Bound the sponsor with a `guard` on every network you serve;
pubnet refuses to start without one. `packages/facilitator/test/in-process-controls.integration.test.ts`
exercises each control above against a local network.

## Startup checks

`createStellarFacilitator` refuses a setup by throwing `FacilitatorSetupError`, whose `code` is stable
(the same code as the service's [startup check](/configuration#startup-checks) for the same setting, where
there is one) and whose message names the field to set:

| Code                                    | Meaning                                                                                                                                   |
| --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `config_rpc_missing`                    | A network has neither `rpcUrl` nor `rpc`                                                                                                  |
| `config_sponsor_secret_missing`         | A network has no `sponsorSecret`                                                                                                          |
| `config_pubnet_rpc_insecure`            | A pubnet RPC URL does not use `https`                                                                                                     |
| `config_pubnet_guard_missing`           | Pubnet has no `guard` and not `unguarded: true`                                                                                           |
| `config_pubnet_fee_ceiling_missing`     | Pubnet has no `policy.maxTransactionFeeStroops` or `policy.inclusionFeeStroops`, or serves `upto` without `upto.maxTransactionFeeStroops` |
| `config_pubnet_inclusion_floor_too_low` | The pubnet inclusion fee (or `inclusionFee.floor`) is below 200 stroops without `allowInclusionFeeBelowFloor: true`                       |
| `config_pubnet_assets_missing`          | Pubnet has no `assets`, or an empty list                                                                                                  |

Other malformed values (a channel count below 1, an invalid seed, a non-canonical `upto` contract without
its WASM hash) throw a plain `Error` naming the field.

## What you give up

- **Bazaar.** Cataloging and discovery live in the Rail402 service, not in the facilitator package. An
  in-process facilitator does not catalog resources.
- **Operations.** Readiness checks, metrics, the sponsor balance polling and the `upto`
  contract's TTL keeper are part of the service. Monitor the sponsor's balance yourself (and feed it to
  `SponsorBudget`), and run `facilitator.reconcile()` at startup and periodically, as the example does.

An in-process facilitator has no dependency on Rail402's hosted service: it talks to the Stellar RPC you
configure, and the upstream `@x402/stellar` verifier reads its ledger-time estimate from public Horizon
(falling back to 5 s when Horizon cannot be reached). Its integration tests run with every request to a
`rail402.dev` host refused.
